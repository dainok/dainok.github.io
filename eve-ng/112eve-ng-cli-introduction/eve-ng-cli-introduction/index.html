    EVE-NG CLI - Introduction¶

    Andrea Dainese advanced eve-ng

    If you've used EVE-NG seriously — not just for a quick lab, but for building complex topologies you need to tear down and rebuild regularly — you've probably felt the friction. Every time you want to recreate a lab, you're back in the browser: create the lab, add nodes one by one, pick images from dropdowns, wire interfaces by hand, configure management access. It works, but it doesn't scale, it isn't repeatable, and it's completely impossible to version-control.

    I'm a network engineer. I'm used to treating infrastructure as code. EVE-NG has a REST API, and I figured: how hard can it be to write a CLI that speaks to it properly?

    This project is the answer to that question. It's still early — a proof of concept, really — but the core workflow is already useful enough that I'm sharing it.

    What it does¶

    EVE-NG CLI is an interactive shell that connects to your EVE-NG server and lets you manage it from the terminal. Tab-completion, command history, colour-coded output. Under the hood it's all async Python, so operations that can run in parallel do.

    The most powerful feature is lab import from a YAML file I call an HLD — High-Level Design. You describe your topology: nodes, images, interfaces, links. The CLI handles the rest: creates the lab, provisions every network and node, wires the interfaces, attaches the management network to NAT, and pushes startup configs for IOL devices. A 10-node lab goes from YAML to fully-wired in about five seconds.

    The full framework¶

    EVE-NG CLI is one piece of a broader framework designed to make EVE-NG labs fully repeatable and code-driven. The three components are:

    • IaC-ready images: pre-configured node images that are accessible via SSH from the moment they boot, through a dedicated Out-of-Band management network. No console access required, no manual first-boot configuration.
    • EVE-NG CLI: an interactive terminal interface that builds complete labs from YAML files describing the topology — nodes, images, interfaces, links. One command, fully-wired lab.
    • Node configuration: (optional, work in progress — not yet public)

    Scripts that connect to each node over the OOB network and push feature configuration described in the HLD. The topology comes up, the config follows automatically.

    This post focuses on the first two. Node configuration will get its own post when it's ready for public use.

    Why share it now, at POC stage?¶

    Because the direction the project takes should come from people who actually use EVE-NG. I have my own workflow and my own pain points, but I'm one person. If you're an EVE-NG power user and there's a workflow you wish you could script or automate, I want to hear about it before I spend weeks building the wrong thing.
