    Introduction to Ansible Automation¶

    Andrea Dainese ansible beginner

    Ansible is often described as an agentless automation framework. However, it relies on Python, which must be installed along with certain modules on the hosts where playbooks are executed. In this sense, Python acts as the necessary "agent" on the remote system.

    Originally designed to automate Linux hosts, Ansible has expanded to support various systems, including Windows, networking devices, and security appliances.

    In this series, we'll focus on using Ansible for automating network devices. For these purposes, Ansible truly functions in an agentless manner.

    Declarative vs. Procedural¶

    There are two main approaches to automation: declarative and procedural.

    • Declarative Approach: You define the desired state of a system. The automation system figures out the steps to transition the current state to the desired state. Terraform is a popular example of this approach.
    • Procedural Approach: You specify the exact steps the automation system must take to achieve the desired state. This method is generally more intuitive as it follows the human thought process of breaking tasks into smaller sub-tasks. Troubleshooting is also simpler due to the absence of underlying "magic." Ansible is a prime example of this approach.

    Ansible is often considered a hybrid system because some modules allow for declaring a desired state, which Ansible then translates into multiple sub-tasks. For instance, the community.vmware.vmware_guest module can create a virtual machine in a single task (declarative), but the VM depends on a pre-existing vSwitch (procedural).

    There's also a third concept to consider: immutability. An immutable approach involves defining instances that cannot be modified. Any change requires redefining the instance from scratch. This approach is common in container management and can be applied to network automation through golden configurations.

    Pros and Cons of Ansible¶

    Understanding the strengths and weaknesses of Ansible will help determine if it's the right framework for your project.

    Pros:

    • No Programming Skills Required: Ansible uses YAML for its playbooks, which is human-readable and does not require complex programming knowledge. This lowers the entry barrier, allowing network engineers and administrators to automate tasks without needing to learn a programming language.
    • Idempotency: Ansible ensures that running a playbook multiple times will result in the same state on the managed hosts. This feature reduces the risk of errors and ensures consistency across deployments, making it reliable for continuous integration and delivery pipelines.
    • Procedural Approach: Ansible playbooks follow a step-by-step approach, which aligns with the way humans naturally think about task execution. This makes playbooks easier to write, understand, and debug. It allows for clear and organized automation workflows.
    • Integrated Documentation: Tasks within Ansible playbooks can include descriptions and comments. This serves as in-line documentation, making it easier to understand the purpose and function of each task without needing separate documentation files.
    • Compliance Checks: Ansible playbooks can be used to verify if network devices or systems comply with predefined configurations. This ensures that configurations adhere to company policies and standards, enhancing security and governance.
    • Standardization: Playbooks provide a standardized method to execute tasks and manage configurations. This promotes consistency across different environments and reduces the variability and errors caused by manual processes.
    • Reusable Code: Ansible allows for the reuse of roles and collections across multiple playbooks. This encourages modular design and reduces duplication of code, saving time and effort in maintaining automation scripts.
    • Sensitive Data Protection: Ansible Vault can encrypt sensitive data like passwords and API keys. This enhances security by ensuring that sensitive information is not exposed in plain text within playbooks.
    • Troubleshooting: Ansible allows isolating and running individual steps to identify and fix errors. This makes the debugging process more straightforward, as you can focus on specific tasks that may be causing issues.
    • Multiple Connection Methods: Ansible can connect to managed nodes using various methods like SSH, local connections, WinRM, and network connections. This flexibility allows Ansible to manage a wide range of devices and platforms, increasing its applicability in diverse environments.
    • User Interfaces: Tools like Ansible Tower and AWX provide graphical interfaces for managing Ansible automation. These interfaces simplify the execution and monitoring of playbooks, making it easier to manage large-scale automation.

    Cons:

    • Performance: Ansible's performance can be slower compared to other automation tools, especially in large-scale environments. Optimizing playbooks for speed requires specific strategies.
    • Complexity in Statements: Writing complex logic in playbooks, such as conditional statements (if-then-else) and loops, can be non-intuitive. This can make playbooks harder to read and maintain, requiring a deeper understanding of Ansible’s syntax and capabilities.
    • Troubleshooting: Debugging playbooks can be complex and time-consuming. Errors can be hard to trace, especially when dealing with large playbooks or complex workflows. Effective troubleshooting often requires experience and familiarity with Ansible.
    • Limited Callback Plugins: The options for customizing output and logging via callback plugins are limited. Ansible tends to operate as a stand-alone system, making it harder to integrate with some external monitoring and logging tools.
    • Breaking Changes: Major Ansible versions can introduce changes that break existing playbooks. This requires continuous updates and testing of playbooks to ensure compatibility, adding maintenance overhead.
    • Module Limitations: While Ansible supports a wide range of platforms, not all platforms are equally supported. Some platforms might lack comprehensive module support, necessitating custom module development or workarounds.

    By understanding these pros and cons, you can better determine whether Ansible is the right automation tool for your specific needs and projects.

    Ansible Components¶

    Understanding the core components of Ansible is essential to effectively using this powerful automation tool. Each component plays a crucial role in how Ansible functions and interacts with managed hosts. Here's a detailed look at the key components:

    • Data Format: YAML. YAML (Yet Another Markup Language) is a human-readable data serialization standard that Ansible uses to define playbooks and variable files. YAML’s readability makes it easy for users to write and understand Ansible playbooks without requiring extensive programming knowledge. Its structure is straightforward and intuitive, reducing the likelihood of syntax errors.
    • Templating: Jinja. Jinja is a templating engine for Python, which Ansible uses to render dynamic content in playbooks. Jinja2 allows for the creation of flexible and dynamic configurations. With Jinja, users can use variables, control structures (like loops and conditionals), and filters to generate configuration files or scripts dynamically based on the specific needs of each host.
    • Parsers: TextFSM, NTC-Templates, PyATS, TTP... Parsers are tools that Ansible uses to process and convert raw text data into structured data.
    • Plugins: Python. Plugins extend Ansible’s core functionality. They are small pieces of code written in Python that can be used to add new capabilities to Ansible.

    Several interfaces can simplify playbook execution, such as:

    • Ansible Navigator: A command-line tool that provides an enhanced user experience for running and troubleshooting playbooks.
    • Ansible Tower: A web-based interface that provides enterprise-level features like role-based access control, job scheduling, and logging.
    • Red Hat Ansible Automation Platform: A complete enterprise framework for automating across IT operations, including security, network, and infrastructure.
    • AWX: The open-source version of Ansible Tower, providing a web-based interface and API for managing Ansible playbooks.
    • ARA Records Ansible: A tool that records Ansible playbook runs and provides reporting and analysis.
    • eNMS: An open-source network management system that integrates with Ansible to provide automation and orchestration capabilities.

    Learning Approach¶

    We'll adopt a learn-by-doing approach, starting with simple cases and gradually expanding them. Documenting your work and maintaining an updated set of recipes will be invaluable for implementing specific scenarios in the future.
