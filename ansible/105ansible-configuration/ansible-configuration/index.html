    Ansible configuration¶

    Andrea Dainese ansible beginner

    Ansible typically works out-of-the-box without requiring additional configuration. However, advanced usage might necessitate some customization. Ansible can be configured through files or variables.

    For example, the DEFAULT_HOST_LIST parameter defines the inventory file. The official documentation specifies:

    • Default: The default value if not specified otherwise (/etc/ansible/hosts).
    • INI* How to specify the parameter in an INI configuration file (in this case, the section is [defaults] and the parameter is inventory).
    • Environment: The environment variable name to specify this parameter (ANSIBLE_INVENTORY).

    If you choose to configure Ansible via INI files, you have four options:

    • Use the file at /etc/ansible/ansible.cfg
    • Use the file ~/.ansible.cfg in the home directory
    • Use the file ./ansible.cfg in the current directory
    • Use the file defined by the ANSIBLE_CONFIG environment variable

    The DEFAULT_HOST_LIST parameter can also be specified on the command line with -i. Additionally, some parameters can be defined within a playbook.

    Ansible uses a precedence to determine which parameter value to use if it is specified multiple times. The order is:

    • Configuration settings
    • Command-line options
    • Playbook keywords
    • Variables

    Lower items in the list override higher ones.

    There are handy utilities to get general and specific information about your environment:

    • ansible-config list: Lists all possible variables and how to configure them.
    • ansible-config dump: Prints current values for each variable.
    • ansible-config init > ansible.cfg: Creates a sample configuration file, comprehensive but complex.
    • ansible-config view: Verifies and prints the current configuration.
    DEFAULT_HOST_LIST:
  default: /etc/ansible/hosts
  description: Comma separated list of Ansible inventory sources
  env:
  - name: ANSIBLE_INVENTORY
  expand_relative_paths: true
  ini:
  - key: inventory
    section: defaults
  name: Inventory Source
  type: pathlist
  yaml:
    key: defaults.inventory

    Let’s check the current configuration of the DEFAULT_HOST_LIST variable:

    $ ansible-config dump | grep DEFAULT_HOST_LIST
DEFAULT_HOST_LIST(default) = ['/etc/ansible/hosts']

    Now, modify it using an environment variable and verify the change:

    $ export ANSIBLE_INVENTORY=inventory.yml
$ ansible-config dump | grep DEFAULT_HOST_LIST
DEFAULT_HOST_LIST(env: ANSIBLE_INVENTORY) = ['/Users/dainese/inventory.yml']

    Configuring SSH¶

    There is a particular case that needs careful handling, especially when automating obsolete devices via SSH. Through SSH, we have two important parameters:

    • ANSIBLE_HOST_KEY_CHECKING: Set this to False to avoid host key checking by the underlying tools Ansible uses to connect to the host. In other words, it disables host verification. This variable can be configured in both the [defaults] and [paramiko_connection] sections.
    • PARAMIKO_LOOK_FOR_KEYS: Set this to False to disable searching for private key files. In other words, it disables private key authentication. This variable can be configured in the [paramiko_connection] section.

    Ansible can use either Paramiko or LibSSH to connect to remote devices via SSH. By default, LibSSH is used if found; otherwise, Paramiko is used.

    To force the use of Paramiko, you can use the following configuration:

    [persistent_connection]
ssh_type = paramiko

[paramiko_connection]
host_key_checking = true
look_for_keys = true

    To increase performance or meet specific constraints, you can force LibSSH:

    [persistent_connection]
ssh_type = libssh

[libssh_connection]
host_key_checking = False
look_for_keys = False

    SSH Access to Obsolete Devices¶

    When accessing very old devices, such as those in a lab, you might encounter the following error:

    Unable to negotiate with 169.254.1.21 port 22: no matching key exchange method found. Their offer: diffie-hellman-group-exchange-sha1,diffie-hellman-group14-sha1

    This occurs because the device does not support secure ciphers, while the system you are connecting from no longer supports weak ciphers. You need to modify the ~/.ssh/config file to re-enable the necessary ciphers, knowing this negatively impacts your environment's security:

    KexAlgorithms +diffie-hellman-group-exchange-sha1,diffie-hellman-group14-sha1

    On macOS systems, the + symbol is not recognized, so you must define the entire list of ciphers:

    KexAlgorithms diffie-hellman-group-exchange-sha1,diffie-hellman-group14-sha1,diffie-hellman-group1-sha1

    pylibssh on macOS¶

    The pylibssh library is generally installed with the following command:

    pip install ansible-pylibssh

    On macOS, you might encounter the following error:

    Failed to import the required Python library (ansible-pylibssh)

    This happens because the ansible-pylibssh library, though seemingly installed correctly (pip freeze | grep pylibssh), does not function. You need to install it from source:

    sudo xcode-select --install
brew install libssh libssh2
export CFLAGS="-I $(brew --prefix)/include -I ext -L $(brew --prefix)/lib -lssh"
git clone https://github.com/ansible/pylibssh.git ~/src/pylibssh
pip install ~/src/pylibssh/
