    Preparing VyOS image for UNetLab v3¶

    Andrea Dainese intermediate proxmox unetlab

    As our first image, we choose to use VyOS, which is publicly available on GitHub. We will work from a single host, and later we can distribute our image. Let's download the image to the host:

    wget -O- https://github.com/vyos/vyos-nightly-build/releases/download/1.5-rolling-202409220007/vyos-1.5-rolling-202409220007-generic-amd64.iso > /var/tmp/pveupload-0000

    The image name must strictly follow the regex /var/tmp/pveupload-[0-9a-f]+.

    Upload the image to the unetlab datastore with the correct name:

    pvesh create /nodes/proxmox1/storage/unetlab/upload -content iso -filename vyos-vyos-1.5-202409220007.iso -tmpfilename /var/tmp/pveupload-0000

    Delete the image from the temporary directory:

    rm -f /var/tmp/pveupload*

    Preparing the Template¶

    Next, let's create a temporary VM to install and configure VyOS:

    pvesh create /nodes/proxmox1/qemu -cores 1 -cpu host -cdrom unetlab:iso/vyos-vyos-1.5-202409220007.iso,media=cdrom -memory 2048 -name template-vyos-vyos-1.5-202409220007 -net0 virtio,bridge=vmbr0 -ostype other -scsihw virtio-scsi-single -sockets 1 -tags "unl;template" -virtio0 unetlab:2,format=qcow2,backup=1,iothread=on -vmid 1000 -serial0 socket -vga none

    In this case, we have disabled the graphical card and added a serial interface to be used as a terminal.

    Start the virtual machine:

    pvesh create /nodes/proxmox1/qemu/1000/status/start

    At this point, access the Proxmox host's web interface. Log in with the user vyos and password vyos, then install the operating system onto the disk with the command:

    install image

    The installation will guide you through a few questions:

    [...]
Would you like to continue? [y/N] y
What would you like to name this image? (Default: 1.5-rolling-202409220007)
Please enter a password for the "vyos" user:
Please confirm password for the "vyos" user:
What console should be used by default? (K: KVM, S: Serial)? (Default: S)
[...]
Which one should be used for installation? (Default: /dev/vda)
Installation will delete all data on the drive. Continue? [y/N] y
[...]
Would you like to use all the free space on the drive? [Y/n]
[...]

[...]

    Once the installation is complete, reboot the node with the reboot command.

    As soon as the node is back online, let's configure it to be used by UNetLab. Specifically, we need to set up a management interface, ideally in a dedicated VRF:

    configure
set vrf name mgmt
set vrf name mgmt table 100
set interfaces ethernet eth0 vrf mgmt
set interfaces ethernet eth0 address dhcp
set service ssh vrf mgmt
delete interfaces ethernet eth0 hw-id
commit
save

    Shut down the node:

    pvesh create /nodes/proxmox1/qemu/1000/status/shutdown

    Remove the CDROM and set the boot order:

    pvesh set /nodes/proxmox1/qemu/1000/config -delete cdrom
pvesh set /nodes/proxmox1/qemu/9001/config -boot legacy=c

    Now convert the node into a template:

    pvesh create /nodes/proxmox1/qemu/1000/template

    Verifying the Template¶

    Before continuing, let's verify that the template works correctly. Create a node from the template and check that the first interface has an IP configured via DHCP, and that SSH access is possible with the username and password:

    pvesh create /nodes/proxmox1/qemu/1000/clone -newid 10001 -full 0 -name node-vyos1
pvesh set /nodes/proxmox1/qemu/10001/config -tags "unl;node;user_root" -net0 virtio,bridge=vmbr0
pvesh create /nodes/proxmox1/qemu/10001/status/start

    Once finished, shut down the node and delete it:

    pvesh create /nodes/proxmox1/qemu/10001/status/stop
pvesh delete /nodes/proxmox1/qemu/10001

    If you notice that the template has issues, you can revert it back to a VM and reconfigure it.

    pvesh create /nodes/proxmox1/qemu/1000/config -template 0

    Backup and export¶

    Finally, create a backup:

    pvesh create /nodes/proxmox1/vzdump -storage local -vmid 1000 -mode stop

    You can retrieve the file /var/lib/vz/dump/vzdump-qemu-1000-*.vma* which is the image of our template. This file can be used to recreate the template on other nodes. For simplicity, rename it to vzdump-qemu-template-vyos-vyos-1.5-202409220007.vma.

    Import¶

    If the unetlab datastore is not shared among all hosts in the cluster, you can copy the backup to the other hosts:

    scp /var/lib/vz/dump/template-vyos-vyos-1.5-202409220007.vma root@172.25.82.158:/var/lib/vz/dump

    Then, import the backup, assigning a new ID to the template:

    pvesh create /nodes/proxmox2/qemu -vmid 1001 -archive local:backup/vzdump-qemu-template-vyos-vyos-1.5-202409220007.vma
