      Managing a brownfield Cisco ACI fabric with NaC and Terraform¶

      Andrea Dainese aci advanced cisco netascode terraform

      After using NaC in recent projects, I started wondering whether it would be possible to manage an existing (brownfield) infrastructure with NaC. Within the NaC suite, this capability is provided directly by Cisco.

      Ideally, after using NaC in recent projects, I asked myself whether it would be possible to manage an existing (brownfield) infrastructure with NaC. Within the NaC suite, this capability is provided directly by Cisco.

      In theory, it is possible to import objects from an existing infrastructure into the Terraform state file. Likewise, it should be possible to analyze a Cisco ACI fabric and describe (model) it using the language provided by NaC.

      If everything works as expected, we can safely operate on a brownfield infrastructure using NaC and Terraform. Let’s walk through the process step by step.

      This is an educational post: no one should execute this process in a production environment, as it is highly likely to cause service disruption.

      Analysis of a Cisco ACI Fabric¶

      The first step is relatively straightforward: we need to read the objects from a Cisco ACI infrastructure that are modeled by NaC. In this example, we will limit the scope to Tenants, VRFs, and Bridge Domains (BDs).

      The most direct approach is to use the APIs, which we have already discussed. This time I chose to work with Cobra, the Python SDK downloadable from any APIC at https://172.25.82.1/cobra/_downloads/

      Once the *.whl files have been downloaded, they can be installed with:

      pip install *.whl

      Cobra is a powerful tool, but it has very limited documentation. As a result, understanding how to properly use the SDK can be challenging, and more than once I had to inspect the library’s source code to determine how to use it correctly.

      Let’s start by retrieving all tenants:

      # Get Tenants
fvTenant_objs = moDir.lookupByClass("fvTenant")
for tenant in fvTenant_objs:
    if tenant.name in IGNORED_TENANTS:
        # Ignore tenant
        continue
    nac_tenant_data = {}
    nac_tenant_data["name"] = tenant.name
    if tenant.descr:
        nac_tenant_data["description"] = tenant.descr

      For each tenant, we must retrieve the associated VRFs:

          # Get VRFs
    fvCtx_objs = moDir.lookupByClass('fvCtx', parentDn=tenant.dn)
    if fvCtx_objs:
        nac_tenant_data["vrfs"] = []
    for vrf in fvCtx_objs:
        nac_vrf_data = {}
        nac_vrf_data["name"] = vrf.name
        nac_vrf_data["enforcement_preference"] = vrf.pcEnfPref
        if vrf.descr:
            nac_vrf_data["description"] = vrf.descr
        nac_tenant_data["vrfs"].append(nac_vrf_data)

      And finally, the Bridge Domains:

          # Get BrideDomains
    fvBD_objs = moDir.lookupByClass('fvBD', parentDn=tenant.dn, subtree="children")
    if fvBD_objs:
        nac_tenant_data["bridge_domains"] = []
    for bd in fvBD_objs:
        nac_bd_data = {}
        nac_bd_data["name"] = bd.name
        nac_bd_data["multicast_arp_drop"] = parse_boolean(bd.mcastARPDrop)
        nac_bd_data["ip_dataplane_learning"] = parse_boolean(bd.ipLearning)
        nac_bd_data["unknown_unicast"] = bd.unkMacUcastAct
        if bd.descr:
            nac_bd_data["description"] = bd.descr
        nac_tenant_data["bridge_domains"].append(nac_bd_data)

        # Find VRF
        for child in bd.children:
            if child.meta.moClassName == "fvRsCtx":
                vrf = moDir.lookupByDn(child.tDn)
                nac_bd_data["vrf"] = vrf.name
                break

      As shown in the code, while retrieving the objects we progressively build the NaC-formatted data structure describing Tenants, VRFs, and BDs.

      Since NaC allows us to organize information arbitrarily, we generate one file per tenant:

          # Dump data
    with open(f"data/tenant-{tenant.name}.nac.yaml", "w", encoding="utf-8") as fh:
        nac_data = {"apic": {"tenants": [nac_tenant_data]}}
        yaml.dump(nac_data, fh, default_flow_style=False, sort_keys=False, allow_unicode=True)

      The result is a set of NaC files describing our infrastructure:

      apic:
  tenants:
  - name: NTS_TRAINING
    vrfs:
    - name: PROD
      enforcement_preference: unenforced
    bridge_domains:
    - name: FW_OUTSIDE
      multicast_arp_drop: false
      ip_dataplane_learning: false
      unknown_unicast: flood
      vrf: PROD
    - name: APP
      multicast_arp_drop: false
      ip_dataplane_learning: true
      unknown_unicast: flood
      vrf: PROD
    - name: WEB
      multicast_arp_drop: false
      ip_dataplane_learning: true
      unknown_unicast: proxy
      vrf: PROD
    - name: DMZ
      multicast_arp_drop: false
      ip_dataplane_learning: true
      unknown_unicast: flood
      vrf: PROD

      This is the simplest part. The next step is to import the objects from Cisco ACI into Terraform using the NaC data model.
