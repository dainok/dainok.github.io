    Attacking the Bottle Filling plant¶

    Andrea Dainese attack intermediate ot-ics

    This scenario serves as an introduction to attacking a Modbus-based PLC. The goal is to gradually understand the system’s behavior by monitoring the PLC registers before executing an attack.

    Reconnaissance phase¶

    Before launching an attack, it is crucial to analyze the plant’s behavior. This involves monitoring the PLC registers to identify active ones and understand how they are utilized.

    For this purpose, I developed a small tool that continuously monitors Modbus registers to determine which ones are in use. The tool is available in my GitHub repository.

    To monitor the PLC behavior for 15 seconds, execute:

    ./modbus_monitor.py -i 172.26.104.12 -p 502 -t holding -k 15

    From our observations, only holding registers are used, specifically registers 1, 2, 3, 4, and 16. Notably, register 16 holds a value of 1, warranting further investigation.

    We also identified that these registers store binary information (0 or 1), despite Modbus offering dedicated boolean registers for this purpose.

    The system operates in three phases:

    • Initialization: The conveyor moves the first bottle under the nozzle.
    • Filling: The nozzle opens, filling the bottle.
    • Moving: The conveyor moves the next bottle into position.

    This cycle repeats indefinitely. During a real-world attack, the adversary would likely lack physical visibility of the system’s operation. However, for this lab, we simplify the analysis.

    From the three phases described above, we can observe:

    • Sensors: Used to read the state of the plant. There are two sensors: bottle presence and full bottle.
    • Actuators: Used to alter the state of the plant. There are three actuators: roller and nozzle.

    After observing the plant behavior and associated states for a certain period, we can define that:

    • The only registers in use are holding registers.
    • Five holding registers are used.
    • Holding registers store binary information using 0 and 1.
    • Registers 1, 3, and 16 are set when the roller is moving the bottle and the nozzle is closed.
    • Registers 2, 4, and 16 are set when the roller is stopped and the nozzle is filling a bottle.
    • When analyzing a newly started plant, we find that only registers 3 and 16 are set.

    From this, we can deduce that:

    • Register 16 (actuator) defines the plant state (on/off).
    • Register 3 (actuator) defines the conveyor state (on/off).
    • Consequently, Register 1 (red sensor) defines whether the bottle is full.
    • Registers 2 and 4 change value together.

    They are associated with the nozzle actuator and the green bottle presence sensor, but require further analysis.

    Attack Phase¶

    An attack on a PLC assumes that register values can be overwritten and that the PLC reacts accordingly. Unlike traditional IT systems, PLCs often rely on external inputs without strict validation, making them susceptible to register manipulation.

    In a targeted attack on a PLC, we assume that we can overwrite register values and that the PLC will act accordingly. This might seem paradoxical to those coming from IT: does the PLC act based on overwritten external values (from the attacker) instead of executing its programmed logic?

    The answer is that the attacker manipulates the PLC’s memory registers, much like in a buffer overflow attack.

    In the previous phase, we observed that only holding registers with values 0 and 1 are used, specifically:

    • Register 1: Red sensor, defines whether the bottle is full.
    • Register 2: Requires verification.
    • Register 3: Actuator, defines the conveyor state (on/off).
    • Register 4: Requires verification.
    • Register 16: Actuator, defines the plant state (on/off).

    Now, let’s attempt to force register values by continuously overwriting them. For this purpose, I have developed a small tool that does exactly that: it continuously writes a specific value to one or more Modbus registers of a PLC. The tool is available in my GitHub repository.

    First let's check register 4:

    ./modbus_write.py -i 172.26.104.12 -p 502 -s h 4 1

    We observe that the nozzle remains permanently open:

    We can then complete our analysis:

    • Register 1: Red sensor, defines whether the bottle is full.
    • Register 2: Green sensor, defines whether the bottle is in position.
    • Register 3: Actuator, defines the conveyor state (on/off).
    • Register 4: Actuator, defines the nozzle state (open/closed).
    • Register 16: Actuator, defines the plant state (on/off).

    Now, we can plan various attack scenarios by manipulating the actuators.

    Scenario 1: Plant permanently off¶

    Regardless of sensor states, the plant remains off, even if an operator manually intervenes via HMI.

    ./modbus_write.py -i 172.26.104.12 -p 502 -s h 16 0

    Effect: The production line remains halted.

    Scenario 2: Nozzle Open and Conveyor Stopped¶

    In this attack, the plant is active, the nozzle remains open, but the conveyor does not operate.

    ./modbus_write.py -i 172.26.104.12 -p 502 -s h 3 0 -s h 4 1 -s h 16 1

    Effect: Water waste and potential flooding of the facility.

    In this scenario, the attack script competes with the PLC: the script attempts to stop the motor, while the PLC tries to activate it as soon as the sensor detects a full bottle.

    A more advanced version of the attack also manipulates the two sensors:

    ./modbus_write.py -i 172.26.104.12 -p 502 -s h 1 0 -s h 2 1 -s h 3 0 -s h 4 1 -s h 16 1

    The effect is more stable:

    If the operator tries to turn off the plant via HMI, the action has no effect.

    Scenario 3: Conveyor Active and Nozzle Closed¶

    In this attack, the plant is active, the nozzle remains closed, and the conveyor is continuously running:

    ./modbus_write.py -i 172.26.104.12 -p 502 -s h 1 0 -s h 2 0 -s h 3 1 -s h 4 0 -s h 16 1

    Effect: The production line produces empty bottles.

    Again, if the operator attempts to shut down the plant via HMI, the action has no effect.
